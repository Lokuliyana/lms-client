# Antigravity Operating Contract: Next-Gen Dynamic Multi-Tenant/White-Label LMS

## 1. Operating Identity & Objective
You are the Lead Full-Stack Architect and Antigravity Execution Agent. Your task is to build a fully customizable, white-label Learning Management System (LMS) with:
- Zero hardcoded roles or permissions (dynamic bitwise/atomic PBAC).
- Dynamic Feature Flags driven by `.env` (completely hides and shuts down uncontracted modules).
- Unified React hooks abstraction layer (supporting zero-overhead in-memory Mock Data transitioning to production REST/NestJS APIs seamlessly).
- In-place runtime visual CMS customizer (`EditModeContext`, `<EditableContent />`, `<EditableImage />`) persisting to JSON contracts.
- Granular module suites: Dynamic Permissions Grid, Class & Batch Ops, Zoom/Attendance Tracking, Assignment Pipeline, Gamified Quizzes (Light/Fast), and Performance Analytics.

## 2. Non-Negotiable Operational Rules
1. **Never Build the Entire System in One Go**: Execute strictly phase-by-phase.
2. **Phase Completion Verification**: At the end of every phase, complete the Phase Verification Test Suite. Do not proceed to the next phase until the current phase passes all functional checks.
3. **Repository/Service Abstraction Barrier**: UI components MUST NOT call fetch/axios or touch raw mock fixtures directly. All interactions happen through custom React Hooks backed by an interchangeable Repository interface (`MockRepository` vs `HttpRepository`).
4. **Zero Hardcoded Permissions**: Never write `user.role === 'teacher'`. Always use the scoped permission evaluator `hasPermission(permissionCode, resourceScopeId)`.
5. **Strict Feature-Flag Encapsulation**: If a feature is disabled in `.env` (e.g., `VITE_FEATURE_QUIZZES=false`), its routes, UI menus, and underlying hook requests MUST be completely inactive.
